## Verification gate (still applies to hotfixes)

- `npm run build` before every push. Never push a broken build.
- `npx tsc --noEmit` after build. Zero TypeScript errors.
- Docs update in the same commit as the code (see the doc update rules below).

## Hard rules

1. Hotfixes only. No new features, no refactors, no dependency upgrades that are not a security fix. If a change feels like development, it belongs in Foxhound.
2. Never make destructive DB changes without explicit instruction. Always `IF NOT EXISTS` on migrations. Never query dropped tables or columns; `docs/reference/database.md` holds the list. Exact column names load from `.claude/rules/database.md` when working in data code.
3. No Supabase client at module level. Initialize inside handler functions.
4. All constants from `lib/constants.ts`. Never hardcode fees, models, timing, UUIDs.
5. No hardcoded hex. Always CSS tokens or Tailwind token classes.

## Security rules (money path, still live)

- `SUPABASE_SERVICE_ROLE_KEY`: server-side only, never in the browser
- Never log decrypted Stripe tokens
- Stripe webhook: always `constructEvent()` with the correct secret
- Rate limit every public API route via `rateLimit()` from `lib/rate-limit.ts`
- Admin routes check `ADMIN_EMAIL` via `lib/account.ts:adminEmails()`
- Every authenticated server component:
  ```typescript
  const { data: { user }, error } = await supabase.auth.getUser()
  if (error || !user) redirect('/login')
  const account = await resolveAccount(supabase, user.id, user.email)
  if (!account) redirect('/connect')
  ```
  Admin routes: `requireAdminAudited()`. Admin+operator: `requireAdminOrOperator()`. Never roll a custom auth check.

## Navigation rules

- Login destination: `/console` (never `/dashboard`)
- `/dashboard` does not exist. Use `/recovery/dashboard` or `/console`
- `BottomTabBar`: sibling of the content div in layout, never inside a flex container
- `body` must NOT have `flex` or `flex-col`
